ArithmeticVoronoi: getting started
==================================

This Julia package computes presentations and verified matrix words for
GL(2,O), SL(2,O), and PSL(2,O), where O is the maximal order of one of five
real quadratic fields. It uses OSCAR/Hecke for exact arithmetic and a pinned
polyhedral_common C++ exporter for perfect-form enumeration. Magma is not
required. This is a research package with the completed cases listed below.

 D    Field             Integral generator w       Class number
 5    Q(sqrt(5))        w^2-w-1=0                       1
 8    Q(sqrt(2))        w^2-2=0                         1
12    Q(sqrt(3))        w^2-3=0                         1
13    Q(sqrt(13))       w^2-w-3=0                       1
40    Q(sqrt(10))       w^2-10=0                        2

D is the FIELD DISCRIMINANT, not the radicand. In every case the lattice is
the free O-module O^2 and the action is K-linear. GL includes all scalar
units; GL and SL retain -I. PSL is the separate quotient SL/{I,-I}.

Run the commands below from the repository root, containing Project.toml.
README.txt provides the complete quick start for a fresh checkout.

Get the saved archives
-----------------------

Install Git LFS before cloning, or install it now and run these commands
inside your clone:

  git lfs install --local
  git lfs pull

On Gentoo the package is dev-vcs/git-lfs. LFS holds two frozen archives:
the five-field dataset and the original D5/D8 regression fixtures.
Ordinary Git stores their small pointer files. The backend source is an
external dependency fetched separately by CMake below.
If an archive is a short text file beginning with "version https://git-lfs",
its payload has not been downloaded yet; run git lfs pull.

Restore the regression fixtures when you want to run D5/D8 or the test suite:

  python3 scripts/restore_fixtures.py

The script checks the archive and every file hash, and refuses to overwrite
different existing data. Use --check for verification without extraction.
It requires Python 3.12 or newer. Restored files under results/two_cells/ are
ignored by Git. New runs, caches and expanded datasets are also ignored;
only deliberately selected, versioned archives belong in LFS.

Read the completed results first
--------------------------------

results/FIELDS_WORDS_DATA_REPORT.txt gives the counts, abelianizations and
recorded timings. The supplied archive contains all five fields, explicit
generator matrices and relators, maps, geometric certificates, word examples,
and a copy of the software that verified that particular dataset.

Verify its checksum before unpacking (Python 3, standard library only):

  python3 -c 'import hashlib,json,pathlib; p=pathlib.Path("results/dataset"); m=json.loads((p/"archive_manifest.json").read_text()); assert hashlib.sha256((p/m["archive"]).read_bytes()).hexdigest()==m["sha256"]; print("archive checksum OK")'
  tar -xzf results/dataset/arithmetic_groups_dataset_v1.tar.gz -C results/dataset

The extracted directory is results/dataset/arithmetic_groups_dataset_v1.
For each D, open fields/D12/PRESENTATIONS.txt, for example. Its JSON companions
GL_simplified.json, SL_simplified.json and PSL_simplified.json include the
generator matrices and both Tietze generator maps. These files can be read
without Julia or a C++ build. dataset.json indexes the files and their hashes.
The expanded data occupy about 228 MB; the compressed archive is about 9 MB.

To verify the saved data with the bundled, historically pinned software:

  julia --startup-file=no --project=results/dataset/arithmetic_groups_dataset_v1/software \
    -e 'using Pkg; Pkg.instantiate(;allow_autoprecomp=false)'
  julia --startup-file=no --project=results/dataset/arithmetic_groups_dataset_v1/software \
    results/dataset/arithmetic_groups_dataset_v1/software/scripts/verify_dataset.jl \
    results/dataset/arithmetic_groups_dataset_v1

Add --complete to the last command to replay the full geometric construction
and fresh Tietze isomorphisms. The default algebraic check verifies exact
matrices, relations, maps, invariants and supplied word paths. Neither check
needs a C++ executable. Keep the extracted bundle unchanged so its manifest
continues to match. See DATASET_SCHEMA.md for the verification scope.

Install for new computations
-----------------------------

The local validation platform is Linux with Julia 1.13.2. The build and runtime
also target macOS; .github/workflows/ci.yml includes a macOS job for verification.
Project.toml and Manifest.toml
pin OSCAR 1.8.2, Hecke 0.39.22 and the remaining Julia dependencies.

  julia --startup-file=no --project=. \
    -e 'using Pkg; Pkg.instantiate(;allow_autoprecomp=false)'

For the exporter, install a C++20 compiler and standard library with std::format,
CMake 3.24 or newer, Ninja, Git,
pkg-config, GMP development files, Eigen and Boost.Serialization development
files, and the nauty/Traces development headers and library. CMake requires
an installed nauty/Traces. Python is used for optional native tests, not for building.
The recorded release used GCC 16.2.0, CMake 4.3.4,
GMP 6.3.0, Eigen 3.4.1 and Boost 1.90; other combinations are not yet tested.
Initial Julia installation and backend configuration need network access.
On macOS, use current Xcode Command Line Tools and the Homebrew installation
commands in README.txt. Pass the Homebrew and eigen@3 prefixes to CMake as
shown there; this supports both Apple Silicon and Intel installation layouts.

  cmake --preset release
  cmake --build --preset release
  cmake --install build
  ctest --preset release

One install selects the same all-field exporter in both backend/config.json
and backend/config_fields.json, with its absolute path and SHA256. Installed
build provenance is in backend/backend-build.json. Reinstall after rebuilding
or moving the checkout. These files, binaries and build directories are ignored.

The release preset uses one job and -O1 to reduce compiler memory. For a hard
10 GiB address-space limit, prefix the build command with Linux
prlimit --as=10737418240. CMake verifies the recorded upstream/submodule commits
and consumes the unmodified template headers. The default source cache is
build/_deps/polyhedral_common-src. README.txt gives explicit -S/-B commands
and options for an external build directory or an existing pinned checkout.

CMake checks that the installed Traces interface compiles and links, and stops
with an installation hint when it is missing or unusable. For a nonstandard
installation, set CMAKE_PREFIX_PATH, or Nauty_INCLUDE_DIR and Nauty_LIBRARY.
Stock Traces works through the backend's exact group construction from
generators. CTest checks all five fields and a rejected boundary request.

Backend computations have an outer wall-clock deadline on both platforms.
The default 10 GiB memory budget is a hard virtual-address-space limit via
prlimit on Linux. On macOS it is a resident-memory watchdog using ps, sampled
approximately every 20 ms; it can overshoot between samples. A request records
its actual policy and sampled peak in process.json. Both deadline and watchdog
failures terminate the backend without publishing a completion checkpoint.
For direct run_exporter calls, memory_policy=:resident selects the same
watchdog on Linux, for example when using an ASan binary with large virtual
shadow memory. Ordinary callers can leave memory_policy=:auto.

For a separate Clang ASan/UBSan build and native checks:

  cmake --preset sanitizer
  cmake --build --preset sanitizer
  ctest --preset sanitizer

This does not replace the installed release executable. It instruments the
exporter and instantiated C++ headers; linked dependency libraries retain
their system instrumentation settings. ASan needs a large virtual shadow
address space, so do not impose the address-space limit on sanitizer runs.

Pin and license information is in backend/pins.json and backend/NOTICE.txt.
Dependency sources are fetched into ignored build directories and are not
vendored in this repository or its LFS archives. Our C++ exporter and CMake
build files are retained here. The backend still needs its own
license compatibility review before redistribution as a compiled executable.

Run a field and inspect its output
----------------------------------

  julia --startup-file=no --project=. scripts/run_fields.jl 12

Pass multiple discriminants, e.g. 12 13 40. With no arguments these three
fields run. The pipeline enumerates and independently validates perfect
forms, computes ridge cycles, assembles GL, extracts SL, constructs PSL,
simplifies the presentations with tracked maps, and computes abelianizations.

Outputs are under results/fields/D12/, including:

  field.json                  exact field, class-group and unit metadata
  enumeration.json            forms, stabilizers, facets and neighbours
  two_cells/coverage.json      completeness ledger and loop-file references
  GL_raw.json, etc.            original presentations and geometric maps
  SL_simplified.json, etc.     smaller presentations and both generator maps
  run.json                    stage statuses, elapsed seconds and cache use
  initial_complete_run.json    retained first successful in-process timing

The pipeline's default for D5/D8 reuses the original two-cell fixtures in
results/two_cells/ after the restoration step above. For a separate computation
in any supported field, use the following Julia API to avoid reusing those
baseline fixtures:

  using ArithmeticVoronoi
  R = run_field_pipeline(8; directory="results/my_D8", reuse_baseline=false)

Repeated runs revalidate compatible enumeration caches and replay completed
ridge cycles. An interrupted backend enumeration restarts its queue; incomplete
word paths are diagnostic checkpoints and also restart. Each completed stage
is recorded independently. A new presentation run leaves constructive-word
validation and the literature comparison pending until those are requested.

Matrix to generator word
-------------------------

Run the complete example (D12 by default; another discriminant is optional):

  julia --startup-file=no --project=. scripts/word_example.jl 12

It creates its own results/word_example/D12 directory. The essential API is:

  using ArithmeticVoronoi, Oscar
  R = run_field_pipeline(12; directory="results/my_D12", reuse_baseline=false)
  P = R.enumeration.problem
  g = matrix(P.field, [1 P.generator; 0 1])
  c = matrix_to_word(R, g; target=:SL, cache_path="results/tau_w.json")
  c["word"]
  verify_word_certificate(R, g, c)   # true, or an explicit validation error

The letters index R.simplified[:SL].generator_matrices. Words multiply in
written order; [1,-2] means G1*inverse(G2), and [] is the identity.
target=:GL allows integral invertible matrices with unit determinant;
target=:SL and :PSL require determinant-one input matrices. A PSL word
represents the input modulo +/-I and records the exact SL_lift_sign.

Set simplified=false to use the corresponding raw generator alphabet.
Set certificate=false to return only the word. Complete cached certificates
are replayed and checked on loading. Words are verified, but need not be
shortest or canonical. Arbitrary denominators and semilinear matrices are
rejected. The resource options are max_steps=10000 and timeout=120.0 seconds;
timeout is checked between crossings, not during a single exact operation.
See CONSTRUCTIVE_WORDS_STATUS.md for the termination argument and error kinds.

Compare with Kirchheimer-Wolfart
---------------------------------

After constructing R for D5, D8, D12 or D13:

  comparison = compare_kw(R)

This saves explicit maps in both directions under R.directory/KW/. It uses
the source hashes previously recorded in references/kw_sources.json; it does
not reread the original TeX files or claim to have checked new local copies.
To verify your own copies as well, call:

  compare_kw(R; reference_source_directory="/path/to/transcriptions")

The directory must contain matching KWeng.tex and KWger.tex. These external
transcriptions are not redistributed here. There is no reference comparison
for D40. See KW_COMPARISON.md for the faithfulness argument and the D8
transcription discrepancy; no error in the published paper is asserted.

Tests, timings and common problems
-----------------------------------

With the backend installed and baseline fixtures restored:

  julia --startup-file=no --project=. test/runtests.jl

The original delivery passed 3806 assertions, with separate ASan/UBSan checks;
the saved transcript and verification receipts are under results/. Running
tests updates reports and creates ignored scratch directories. The supplied
dataset archive retains the exact software and receipts of that delivery;
it is not regenerated when this checkout's documentation or code changes.

Ordinary runs use one Julia computation thread. Timings in run.json exclude
Julia/OSCAR startup and may include compilation and cache replay. D40 is much
larger (52 perfect-form orbits, 2618 oriented loops); its saved warm pipeline
timing is not a cold end-to-end benchmark. See the report for stage context.

If you see missing_executable, build and install the exporter as above. If a
binary was moved or changed, regenerate its configuration; do not edit hashes
to force acceptance of an old cache. Incompatible cached geometry or words
must be recomputed in a new output directory. For D5/D8, reuse_baseline=false
selects new ridge data; enumeration caches still depend on the backend hash.
A resource_exhausted word error can be retried with a larger explicit budget.

Repository contents
--------------------

src/, scripts/ and test/ contain the implementation, commands and regressions.
README.txt provides portable installation commands. PRESENTATION_JUSTIFICATION.md
explains completeness; BACKEND_AUDIT.md records backend acceptance and scope.
backend/ preserves our exporter, dependency pins and reference license notices.
results/ contains selected reports and the sealed five-field dataset archive.
test/fixtures/ contains the compressed D5/D8 regression archive and checksum
manifest. Both .tar.gz archives use Git LFS. Expanded fixtures and bundles,
current field runs, executable files, local configurations and scratch data
are ignored. Keep new per-run output local; add a new frozen archive only
when intentionally preserving a dataset version.
Historical receipts describe the original execution environment, including
paths that need not exist in a fresh clone. Consult this guide for portable
commands. The separate Ford/HSR experiments are outside this repository.
